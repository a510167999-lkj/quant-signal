# 生产可用性进一步优化设计

## 目标

在不购买 Tushare 的前提下，进一步提升个人 A 股推荐系统的生产可用性和可解释性。本轮包含三个范围：

1. 将 MOOTDX 接入为 AKShare 历史行情失败时的安全应急备用。备用路径不尝试生成完整前复权历史，只在已有可信 qfq 缓存且期间无新的除权除息事件时，用 MOOTDX 原始日线补齐缓存之后的交易日。
2. 为每次推荐保存过滤漏斗和每个候选的淘汰原因，使“今天为什么 0 只推荐”可直接解释。
3. 将生产健康状态区分为核心行情链路和增强上下文链路，行业、新闻、公告或资金流失败时降级但不阻断基础推荐。

## 已验证事实

- 本地和 VPS 均能获取股票、ETF 的 MOOTDX 日线，最新 OHLC、volume、amount 与 AKShare 缓存一致。
- `frequency=9` 才使用与现有系统一致的日线/成交量口径；单次最多 800 根。
- MOOTDX 0.11.7 内置 qfq/hfq 与 pandas 3.0.3 不兼容，且依赖新浪复权因子，不能作为安全前复权来源。
- MOOTDX 自带服务器列表大量失效，端口可连不代表行情请求可用。

## 架构

### 新的 MOOTDX 日线适配器

新建独立模块，不复用当前只面向 L1 的容错逻辑。该模块负责：

- 显式映射上海、深圳、北交所代码，包括新 `920xxx` 代码。
- 固定使用整数 `frequency=9`，拒绝任意字符串频率。
- 按 `start=0,800,1600...` 分页，直到覆盖需要的开始日期或返回短页。
- 将 `datetime` 转为 `date`，全局排序、去重并裁剪日期。
- 用真实 `bars` 请求和非空/最新日期校验服务器；连接失败、返回 False、空数据和协议错误都必须切换下一台。
- 在 `finally` 中关闭客户端，每台超时受限，整个备用请求有总时间预算。

### 安全增量合并

MOOTDX 适配器只返回明确标记为未复权的原始日线和 XDXR 事件。市场数据层负责判定能否与 qfq 缓存合并：

1. `adjust=""`：可在 AKShare 两条路径都失败后直接使用 MOOTDX 原始日线。
2. `adjust="qfq"`：必须存在同一 symbol/market/adjust 的可信 SQLite 缓存，且数量满足策略最小需求。
3. 获取缓存最新日期之后的 XDXR 事件；任何分红、配股、送转、缩股、ETF 份额折算都阻断合并。
4. 无新事件时，只取 MOOTDX 中晚于缓存最新日期的行，与原 qfq 缓存合并。
5. 合并后必须通过 OHLC、日期、成交量、成交额和价格连续性校验；失败则不写入 qfq 缓存。
6. 无可信缓存、XDXR 请求失败或检测到新事件时，qfq/hfq 请求必须失败或回退到尚在安全时限内的旧缓存，绝不返回原始价。

`hfq` 不做增量合并，因为后复权最新价并不与原始价锚定；AKShare 失败时明确拒绝。

## 数据质量门槛

- 每行必须满足 `low <= open/close <= high`，价格为正，volume/amount 非负。
- 日期必须唯一、严格升序、不得出现周末。
- 最新日期不得早于系统预期的最近交易日，盘中按已完成 K 线规则判断。
- 连续性默认用缓存最后收盘与新增首根收盘比较；超过正常涨跌停容差时阻断。
- `frequency=9` 的 volume 单位按“手”写入现有 schema，amount 按“元”写入；抽样验证 `amount ≈ 成交均价 * volume * 100`。
- 停牌零量日保留但打标，不人为填补缺失交易日。

## 配置与观测

- 新增 `ENABLE_MOOTDX_DAILY_FALLBACK`，默认关闭，经本地和 VPS 验收后再打开。
- 复用 `MOOTDX_SERVERS`，但日线适配器对每台执行业务探针，不相信自带服务器列表。
- 新增总预算和最大分页数配置，防止多服务器乘多分页放大等待。
- 返回 source 明确区分 `MOOTDX raw daily fallback` 和 `MOOTDX incremental qfq fallback`。
- provider 状态记录服务器尝试数、页数、行数、最新日期、XDXR 门槛结果和失败原因，不记录敏感配置。

## 推荐过滤漏斗与审计快照

每次推荐快照的 `summary` 新增 `selection_funnel`，使用稳定机器可读阶段名并保存输入数、通过数和淘汰数。至少包含：

- 全市场快照数。
- 基础/流动性预筛后数量。
- 行业候选池数量与是否使用全市场回退。
- 深度分析成功、分析失败和冷却期跳过数量。
- 操作类型/评分、严格信号、历史质量、公告、新闻、资金流和最终上限各阶段淘汰数。

每个被淘汰候选保存最早的决定性原因，例如 `cooldown`、`analysis_error`、`market_action`、`score_below_floor`、`strict_signal_failed`、`strategy_quality_failed`、`announcement_blocked`、`news_blocked`、`fund_flow_blocked`。审计文件不保存新闻全文、鉴权信息或私人持仓。

完整审计快照写入独立 JSONL 路径，最新推荐 API 仅返回聚合漏斗和有限样例，避免响应无界增长。即使最终为 0 只，也必须写入完整漏斗。

## 核心与增强链路分级

- **核心**：交易日历、全市场快照/可用候选池、单股日线、推荐任务状态和任务锁。主备行情均不可用、缓存超出安全时限或推荐任务失败时为 `unhealthy`。
- **增强**：行业、新闻、公告、资金流、L1 与融资融券上下文。单个或多个失败时为 `degraded`，推荐继续使用可用信号，并在漏斗/快照中记录未使用的增强层。
- 增强链路的“高风险内容明确阻断某只候选”仍是正常业务决策，不等于 provider 故障。

生产健康结果返回 `core_status`、`enhancement_status` 和总体 `status`；总体依然取最严重级别，但告警文案明确说明是基础推荐不可用还是增强因子缺失。

## 测试与验收

本地必须先通过以下确定性测试：

- 沪/深/北股票与沪/深 ETF 路由，包括 `920xxx`。
- 只有 frequency 9 可用，字段/单位标准化正确。
- 超过 1,600 根的分页、排序、去重和日期裁剪。
- 第一台超时、连接 False、请求异常、空页后能切第二台，全部 client 关闭。
- qfq 无缓存、XDXR 失败、分红、配股、送转、ETF 折算均阻断；无事件时只追加新日线。
- 未复权请求可在 AKShare 失败后直接使用 MOOTDX。
- hfq 在 AKShare 失败时拒绝。
- 服务器失败、事件阻断和数据质量失败绝不污染任何 adjust 缓存。
- 最终 0 只推荐仍产生完整漏斗，各阶段计数守恒，同一候选只有一个决定性淘汰原因。
- 审计 JSONL 即使部分候选分析抛错也能落盘，且不包含新闻全文、密钥、鉴权头或持仓。
- 健康结果能区分 core/enhancement；增强层失败不能将核心链路标记为故障。

真实网络冒烟覆盖 `600519`、`000001`、`510300`、`159915`，并与现有 AKShare 缓存比对最新 20 日的 OHLC、volume、amount。本地全量测试和 Ruff 通过后才允许在 VPS 打开开关。

## 不在本轮范围

- 用 MOOTDX 替代行业、公告、新闻、资金流或交易日历。
- 实现完整的项目自有 qfq/hfq 复权引擎。
- 对现有选股、评分、风控或推荐门槛做任何改动。
- 增加自动交易、券商委托或实际仓位变更。
