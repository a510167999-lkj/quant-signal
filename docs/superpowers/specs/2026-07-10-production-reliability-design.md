# 生产可靠性闭环设计

## 目标

为个人 A 股推荐系统建立可重复执行的生产健康检查和异常提示闭环，覆盖 VPS 定时任务、最新推荐、数据新鲜度、provider 状态和告警通路。本轮不改变选股策略、不自动下单，也不引入新的监控平台。

## 实施顺序与门槛

必须严格按两个阶段执行：

1. **本地阶段**：完成设计、测试驱动实现、全量测试、静态检查、CLI 冒烟测试和失败场景验证。
2. **VPS 阶段**：只有本地门槛全部通过后才能开始。先做只读核查，确认实际 service/timer、数据和日志状态；再部署本项目范围内的改动，最后做生产验收。

本地门槛包括：新增定向测试通过、全量 `pytest` 通过、`ruff check .` 通过、健康 CLI 的健康/降级/故障退出码符合约定，且输出不包含 token、密码或完整鉴权信息。

## 架构

采用“应用内业务健康检查 + VPS 运维检查”双层架构。

### 应用健康检查

新建独立的生产状态模块，只负责读取现有运行产物并产生结构化判定，不触发推荐扫描或数据抓取。每项检查返回：

- `name`：稳定的机器可读名称。
- `status`：`healthy`、`degraded` 或 `unhealthy`。
- `message`：可直接用于运维定位的简短中文信息。
- `observed_at` 及必要的非敏感证据，如文件更新时间、最新交易日和失败次数。

总体状态取最严重的子状态。任何单项检查的解析错误必须转换为结构化 `unhealthy` 结果，不得使整个状态命令崩溃。

### API 与 CLI

- 新增受现有 Basic Auth 保护的 `GET /api/production/status`。
- 新增 `python -m app.jobs production-check`，默认输出 JSON。
- CLI 退出码：`healthy=0`、`degraded=1`、`unhealthy=2`。
- `degraded` 表示尚可服务但需要介入，例如备用数据源生效或非关键数据轻微过期。
- `unhealthy` 表示可能导致当日推荐、风控或告警不可信。

### VPS 运维检查

新增项目内的只读检查脚本，负责：

- 检查 `quant-signal`、推荐、监控、计划退出和缓存预热的 service/timer 是否存在、已启用且无 failed 状态。
- 调用本地应用 CLI 生产检查，避免在 shell 中重复业务新鲜度规则。
- 输出简洁汇总和非零退出码，便于手工执行、cron/systemd 捕获或接入现有 webhook。
- 仅在失败时给出有限的最近日志索引，不输出 `.env` 或敏感配置。

## 检查项与判定

### 最新推荐

- 验证文件可读、JSON 结构有效、任务未长时间停留在 `running`。
- 按北京时间和交易日判定应有的最新快照；非交易日不要求生成新推荐。
- “0 只入选”是合法业务结果，不能单独判为故障。
- 如有推荐，必须不超过 3 只，且每只包含入场、止损、止盈、支撑/压力、持有周期和风险说明等现有操作建议字段。

### 任务锁

- 锁不存在或属于正在运行的推荐任务时为健康。
- 锁超过配置的最大扫描时长且无活跃任务证据时为故障。

### 数据新鲜度

- 交易日历是调度判定的关键数据，缺失或过期为故障。
- 日线 SQLite 缓存按最后更新时间和最近交易日评估。
- 行业数据为排名增强层；轻微过期为降级，缺失时明确说明将回退到全市场流动性候选池。

### Provider 状态

- 从现有 AKShare 状态文件读取最近事件，区分单点失败、已恢复失败和连续关键失败。
- 使用 Tushare 且已配置 fallback 时，不将单个 AKShare 失败直接判为整体不健康。
- 不向状态结果写入 token、请求头或完整上游响应。

### 告警通路

- 健康检查本身不重复实现 webhook 客户端，复用现有告警配置与发送机制。
- 仅在总体状态从健康变为降级/故障、故障内容变化，或经过抑制窗口仍未恢复时发送，避免每次检查重复轰炸。
- 恢复到健康时发送一次恢复通知。

## 错误处理和安全

- 所有文件读取和 JSON 解析错误均转换为明确检查结果。
- 检查命令不做自动修复，避免在诊断过程改写生产数据。
- VPS 阶段先只读检查；部署时仅修改 `/home/ubuntu/quant-signal` 及对应 `quant-signal-*` systemd 单元。
- 不读取或输出其他 VPS 项目的配置和日志。

## 测试与验收

本地测试必须使用临时文件和固定化时间，覆盖：

- 交易日的新鲜推荐、陈旧推荐、非交易日和合法空推荐。
- 推荐超过 3 只、操作建议缺字段、长时间 `running` 和陈旧锁。
- 缓存/日历/行业/provider 的健康、降级、缺失和损坏场景。
- API 鉴权和返回结构。
- CLI 三种退出码。
- 告警去重、持续故障重提醒和恢复通知。
- VPS shell 脚本使用伪造的 `systemctl` 和健康 CLI 输出进行本地测试，不需连接 VPS 也能验证分支和退出码。

VPS 最终验收必须保留以下证据：

- 核心 service/timer 的 enabled/active/failed 状态。
- 一次真实 `production-check` JSON 输出和退出码。
- 最新推荐快照的交易日、生成时间和条目数，不暴露具体私人持仓。
- 至少一个本地模拟故障证明异常会导致非零退出，以及一个恢复场景证明状态可回到健康。

## 不在本轮范围

- 新的选股、板块轮动或仓位策略。
- 自动委托、券商接口或实际下单。
- Prometheus、Grafana 或新的第三方监控平台。
- 改动同一 VPS 上的其他项目。
